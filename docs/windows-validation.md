# Windows 11 验收操作手册

当前尚未执行 Windows 验收。以下步骤用于填入 `test-report.md`，不能因脚本存在而标为通过。

## 1. 测试基线与独立运行

记录 Windows 11 版本、系统构建号、CPU 型号、逻辑处理器数、内存、SSD、缩放比例、应用版本、最终 EXE SHA-256、账户权限和显示器布局。参考机器至少 4 逻辑处理器、8 GB 内存且无重后台负载。

使用干净 Windows 11 x64 虚拟机／实体机。检查“已安装的应用”以及 `C:\Program Files\dotnet\shared`，确认未安装 .NET 10 Desktop Runtime/SDK，记录截图；单凭 `dotnet` 不在 PATH 不能证明未安装。只复制 `LiteClicker-win-x64.exe`，断网后普通用户双击，测试两个模式、停止、托盘、配置和重新打开。再在含中文与空格的路径，以及 EXE 目录只读而用户目录／临时目录可写的条件下重复。没有旁置 DLL、deps.json、runtimeconfig.json 或运行库目录。

冷启动：分别记录首次解包、后续至少 5 次从启动进程到窗口可交互的时间。可在进程开始前开启录屏／单调秒表，窗口可交互后停止；记录计时方法，不把编译时间当启动时间。目标首次 ≤8 秒、后续 ≤3 秒。

## 2. 独立消息接收器

在开发验收机运行 `artifacts/test-target/LiteClicker.TestTarget.exe`，它是独立进程，不会被应用的自身窗口保护阻止。将两个窗口放在不同位置。

- 点“清空记录”，鼠标移至蓝色区域，F7 按住 10 秒，再 F7 释放。带 LiteClicker 标记的按下和抬起应各一次，中间没有重复按下。移动鼠标可观察框选。
- F6/F7 切换应先释放旧按住再进入另一模式；F8 后不得残留按住。
- 接收器记录原始 WM_LBUTTONDOWN、WM_LBUTTONDBLCLK（也算按下）和 WM_LBUTTONUP。不要根据业务 Click 回调计数。
- 手动点击操作界面没有 LiteClicker 标记；分析工具仅计带 `0x4C434B52` 标记的消息。该标记仅用于测试，不代表目标软件业务接受。
- 测试完成先按 F8，再导出 CSV。记录上限 500,000 条；达到上限的 CSV 不可用于验收。

## 3. 固定 60 秒频率测量

对 1、5、10、20、37、50、100 次/秒分别测量。默认延迟 2 秒。

1. 设置目标频率。在接收器点“5 秒后开始 60 秒测量”，立即把鼠标移至蓝色区域并按 F6。
2. 第 2 秒左右开始点击，第 5 秒开始固定测量窗口；约 3 秒用于暖机。若启动延误到测量窗口内，本轮无效，应重测。
3. 到第 65 秒接收器显示“固定 60 秒已完成”后，按 F8，导出 CSV。
4. 运行 `scripts/analyze-target.ps1 -CsvPath <导出文件> -TargetCps 37`。其他频率替换参数。

计数规则：接收器 Stopwatch 的半开窗口 `[start, start + 60 秒)` 中，带标记的 DOWN 和 DBLCLK 总数除以 60。边界处 DOWN/UP 可落入不同窗口，按下频率和完整输入对提交计数不能混为一谈。分析器拒绝未结束窗口、无测量起点或记录溢出；仍需人工确认暖机和鼠标始终位于目标。1–20 次/秒偏差 ≤10%，21–100 次/秒偏差 ≤15%。

## 4. 停止响应与长时间运行

退出已有应用，使用 `LiteClicker-win-x64.exe --diagnostics` 启动。诊断只写停止摘要，默认不启用。

在 1 次/秒、50 次/秒和按住模式分别做至少 10 次独立 F8 停止，每次新启动后等到实际运行，再停止，留至少 1 秒间隔。不计重复按 F8 的空闲样本。检查 `%LOCALAPPDATA%\LiteClicker\stop-0.csv`（有轮转时合并 stop-1/2）：每个有效样本 `pendingRelease=False`，`stopLatencyMs≤150`；需要释放时有 `releasedSeconds`。同一行的 requested、lastDown、released、completed 都使用进程内同一单调时钟。已进入临界区的输入可能在停止请求到达后完成；停止生效后不再有新按下。接收器消息到达时间受消息队列影响，不能替代提交和清理时间。

50 次/秒连续 30 分钟、按住连续 10 分钟，各自结束后确认停止／释放，期间没有冻结或任务叠加。记录接收消息、输入计数和资源曲线。按住会进行约 25 ms 周期的自身窗口检测，停止按住不会等到点击周期。

## 5. CPU、内存和资源

先通过任务管理器确认 LiteClicker 的 PID，且没有重后台负载：

```powershell
.\scripts\measure-process.ps1 -ProcessId 1234 -Seconds 60 -OutputPath idle.csv
.\scripts\measure-process.ps1 -ProcessId 1234 -Seconds 60 -OutputPath click50.csv
.\scripts\measure-process.ps1 -ProcessId 1234 -Seconds 1800 -OutputPath click30min.csv
.\scripts\measure-process.ps1 -ProcessId 1234 -Seconds 600 -OutputPath hold10min.csv
```

第一轮保持空闲；后续按对应情景操作。脚本按总进程 CPU 时间差 ÷ 单调经过秒数 ÷ 逻辑处理器数计算整机百分比，每秒记录工作集、私有内存、线程、句柄，并输出机器与版本摘要。目标空闲 CPU <1%/工作集 <200 MiB；50 次/秒 CPU <5%/工作集 <250 MiB。长时运行检查稳态趋势，不能把启动 JIT／GC 波动直接判为持续增长。脚本仅用于有权限查询的测试进程。

## 6. 交互、错误与生命周期

逐项执行需求 AT01–AT27，尤其：

- 100%、125%、150%、200% DPI 与不同 DPI 的双显示器（包含负坐标）。窗口移到另一屏幕、拔除屏幕、重启恢复窗口；开始／停止应一直可操作，内容可滚动，Tab 焦点可见。
- 先保持左键按下再触发启动，或把指针停在自身窗口至倒计时结束；不能产生首个按下。运行中进入自身窗口，连点停止／按住释放。
- 最小化后 F6、F7、F8 正常；托盘打开菜单和恢复先停止；两个模式下分别关闭与 Alt+F4。
- 锁屏／注销／睡眠前运行，恢复后保持停止。不要在未保存其他工作时测试注销。
- 先退出应用，在接收器中占用 F6，再启动应用：显示冲突且禁用启动。改为可用绑定后启动；重复绑定拒绝；注册失败回滚必须与实际绑定一致。
- Ctrl+Shift+F6 等组合保持按住：延迟已过仍不能开始，松开才开始；5 秒不松开则取消。等待期间 F8 有效。
- 同一用户会话重复启动、普通→管理员和管理员→普通的重复启动：已有实例停止显示或明确无法唤醒，新进程不能运行第二个引擎。不同权限唤醒可能受 UIPI 阻止。
- 备份配置后测试 JSON 损坏、缺字段、未知版本与不可写目录；检查合法字段保留、默认回退、未知版本备份和写入失败提示。恢复原配置与目录权限。
- 普通权限应用操作管理员接收器：不假设可注入；提交失败时提示权限／桌面状态而不声称精确识别 UIPI。

返回 0、部分成功、释放失败、过期会话和停止边界由 xUnit 可重复模拟；不要用强制结束进程来假装释放失败测试。Windows 实机仍须核对 UI 对这些状态的显示。

验收完成后将实际环境、数据、截图、原始 CSV、TRX 和 SHA-256 与报告关联。未做的项目仍写“未执行”。
