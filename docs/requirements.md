# Windows 11 鼠标连点器项目需求文档

版本：1.0  
编写日期：2026 年 11 月 16 日  
暂定产品名：轻点连点器 LiteClicker  
面向对象：负责实现、测试、打包和交付的 AI Agent

> 本文是可直接执行的开发规格。Agent 应据此交付完整的 Windows 桌面应用、源代码、构建脚本和测试记录。本次文档制作不代表应用已经开发或验证完成。

## 1 项目目标与完成定义

制作一款在 Windows 11 上使用的鼠标工具，提供两个核心功能：鼠标左键连续点击，以及鼠标左键持续按住。用户通过中文图形界面配置，通过全局快捷键控制；最终只需取得一个 EXE 文件，即可在符合目标系统要求的电脑上离线运行。

用户已明确的要求：

1. 支持 Windows 11。
2. 支持鼠标左键连续点击，并能调节档位。
3. 支持鼠标左键持续按住。
4. 提供 GUI 图形化界面。
5. 最终打包为 EXE，使用者无需另行安装开发环境或应用运行框架。

本文补充决定技术栈、默认参数、界面规范、快捷键、异常处理、测试方法和交付内容。未标注为可选的要求均属于首版必须完成的范围。

最终完成需要同时满足：源代码可构建、两种模式真实可用、停止和释放行为正确、单 EXE 在干净 Windows 11 环境中运行通过。仅提供界面原型、代码片段或未经验证的发布命令，不构成完成。

## 3 技术方案

| 层次 | 规定方案 | 选择原因 |
| --- | --- | --- |
| 编程语言 | C#，使用 .NET 10 SDK 默认的稳定语言版本 | 适合 Windows 桌面开发，便于维护 |
| GUI | WPF 与 XAML | 提供桌面控件、数据绑定与 DPI 适配能力 |
| 运行框架 | .NET 10 LTS，采用实施时可用的受支持补丁版本 | 适合需要持续维护的桌面应用 |
| 界面结构 | 轻量 MVVM | 将界面、运行状态与输入实现分离 |
| 鼠标输入 | Win32 SendInput，通过 P/Invoke 调用 | 使用 Windows 提供的输入接口 |
| 全局快捷键 | RegisterHotKey、UnregisterHotKey、WM_HOTKEY | 窗口失焦或最小化时仍能控制 |
| 托盘 | System.Windows.Forms.NotifyIcon | 与 WPF 集成，提供显示、停止和退出入口 |
| 本地设置 | System.Text.Json | 不引入额外运行依赖 |
| 发布 | win-x64、自包含、单文件 | 将所需 .NET 运行时随应用交付 |
| 自动化测试 | xUnit 或 MSTest，选一种并锁定版本 | 验证状态、输入序列、参数和并发行为 |

依赖以 .NET 标准库为主；首版不引入大型 UI 框架、数据库、嵌入式浏览器、系统服务或鼠标驱动。测试依赖不得成为最终 EXE 的运行前提。

开发环境需要 Windows 11 和 .NET 10 SDK。编辑器可使用支持该 SDK 的 Visual Studio 或 VS Code，构建不能依赖某位开发者电脑上的绝对路径。用 global.json 固定实际使用的 SDK 版本，并在构建说明中记录。

技术依据见第 16 节。具体发布设置属于本项目的实现选择，仍须通过最终 EXE 验证，不能仅根据文档推断兼容性。

## 4 核心功能需求

### FR01 连续点击

- 启动后，按照选定频率持续产生完整的左键按下与抬起序列，直到停止。
- 一次点击定义为一组 LEFTDOWN 和 LEFTUP；连点首版将两者在同一次 SendInput 调用中按顺序提交，不提供单次按压时长设置。
- 不移动、不锁定鼠标指针。用户移动鼠标后，后续点击作用于新位置。
- 不绑定某个程序或窗口；目标由当时的指针位置和 Windows 的输入分发决定。
- 操作系统或目标软件可能把较快的点击识别为双击；本项目不修改 Windows 双击设置。
- 运行期间显示“连点中”、目标频率、本次运行时间以及“已发送 X 次”。计数只表示已完整提交的输入对，不表示目标应用完成了某项操作。
- 本次运行时间从首次成功提交完整点击对或按住事件时开始，到停止请求生效时结束，不包含启动倒计时。
- 本次计数使用 64 位整数；新一次启动时清零，停止后保留供查看。倒计时取消不覆盖上一次结果。

### FR02 档位和自定义频率

| 档位 | 显示名称 | 目标频率 | 理论周期间隔 |
| --- | --- | --- | --- |
| 1 档 | 慢速 | 1 次每秒 | 1000 毫秒 |
| 2 档 | 较慢 | 5 次每秒 | 200 毫秒 |
| 3 档 | 标准 | 10 次每秒 | 100 毫秒 |
| 4 档 | 快速 | 20 次每秒 | 50 毫秒 |
| 5 档 | 高速 | 50 次每秒 | 20 毫秒 |
| 自定义 | 自定义速度 | 1–100 次每秒，整数 | 1000 ÷ 频率，单位为毫秒 |

- 默认选中 3 档。点击预设档位时，数字框同步更新；手动输入数字时，切换为自定义。
- 数字框是自定义值的权威输入；可配滑块，但不允许只能使用滑块调整。
- 理论间隔只读显示，最多保留两位小数，不把显示舍入结果用于内部计时。
- 空值、零、负数、小数、非数字、超出范围均显示字段级错误，并禁止启动；不默默截断或替用户改值。
- 编辑过程中不弹出连续模态提示。失焦或提交时校验；启动前必须再次校验。
- 速度、模式选择和启动延迟仅在停止状态下编辑，运行或倒计时期间禁用。
- 在按住模式下隐藏或禁用速度区域，并说明“按住模式不使用点击频率”；保留上一次连点速度。

### FR03 持续按住左键

- 用户触发一次开始动作后，应用发送一次 LEFTDOWN，持续保持模拟左键按下。
- 用户再次触发按住快捷键、点击停止、按紧急停止键或退出时，发送 LEFTUP。
- 此功能是“按一下快捷键开始，再按一下释放”，用户不需要一直按住快捷键。
- 持续按住期间禁止通过循环重复 LEFTDOWN 模拟保持；正常完整会话应只有一次按下与一次抬起。
- 用户可以移动鼠标，目标应用可据此执行拖拽或框选；是否响应由目标应用决定。
- 显示“左键按住中”和持续时间，不显示连点次数。
- 提醒用户按住期间避免同时操作物理鼠标左键。首版不提供对真实鼠标事件的接管和屏蔽，也不承诺自动纠正真实左键输入造成的状态变化。

### FR04 模式互斥

任何时刻至多存在一个活动输入任务。连点与按住不得并发。

| 当前状态 | 用户操作 | 结果 |
| --- | --- | --- |
| 停止 | F6 或选择连点后点击开始 | 按配置倒计时，然后进入连点 |
| 停止 | F7 或选择按住后点击开始 | 按配置倒计时，然后进入按住 |
| 连点中 | F6 | 停止连点 |
| 按住中 | F7 | 释放左键并停止 |
| 连点中 | F7 | 停止连点并清理，再倒计时进入按住 |
| 按住中 | F6 | 先释放左键，再倒计时进入连点 |
| 倒计时 | 与目标模式相同的快捷键 | 取消倒计时，回到停止 |
| 倒计时 | 另一模式的快捷键 | 取消旧倒计时，从完整延迟重新开始另一模式 |
| 任意状态 | 紧急停止 | 取消启动与运行，并处理未释放的模拟左键 |

表内 F6、F7、F8 指默认绑定。用户修改快捷键后，界面、托盘提示与上述行为同步使用新的绑定。

### FR05 全局快捷键

- 使用 RegisterHotKey，并设置 MOD_NOREPEAT，避免长按快捷键造成反复切换。
- 提供三个动作的快捷键编辑和“恢复默认”。编辑仅能在停止状态进行。
- 可选主键为 F1–F11，可附加 Ctrl、Alt、Shift 的任意组合；拒绝 F12、Windows 键组合和三个动作之间的重复绑定。
- 注册结果必须以 Win32 调用返回值为准，不能仅检查应用内部是否重复。
- 任一必要快捷键无法注册时，保持停止状态、禁用所有启动入口，并指出冲突动作和可修改位置。其他设置仍可编辑。
- 新配置需完整注册成功后才替换并保存旧配置。失败时清理新注册，尝试恢复原配置；恢复也失败时继续禁止启动，不能显示虚假的可用状态。
- 退出时释放快捷键。重新启动不能因自身遗留逻辑造成冲突。
- 自定义快捷键可能包含修饰键；启动条件必须等待触发组合键全部松开，避免把 Ctrl、Alt、Shift 带入目标点击。等待过程中仍响应紧急停止，超过 5 秒取消本次启动。
- 启动延迟与松键等待都从本次启动请求计时；只有延迟已经结束且组合键全部松开才可继续。5 秒时仍未松开则取消，不在松键后重复执行一遍延迟。

### FR06 启动延迟与本应用保护

- 点击开始后显示“将在 2 秒后开始，请将鼠标移至目标位置”等明确提示，开始按钮变为“取消启动”。
- 延迟为零时跳过倒计时，但仍执行快捷键松开、指针位置和输入状态检查。
- 倒计时结束后才读取当前指针位置，不使用点击开始按钮时的坐标。
- 若开始时左键当前已处于按下状态，取消启动并提示先松开左键；不把该检查当作持续运行期间区分真实和模拟输入的方法。
- 若即将开始时指针位于本应用的主窗口、设置窗口或其他自有窗口内，取消启动，防止点击自身按钮。
- 连点运行中，每次发送前检查指针下窗口；命中本应用窗口时立即停止。
- 按住期间以不超过 50 毫秒的检查周期检测指针是否进入本应用窗口；命中时释放并停止。
- 实现时依据窗口句柄和所属进程判断，并处理子窗口，不只比较主窗口矩形。多显示器负坐标不能导致判断失效。
- 托盘菜单打开前先停止；由托盘恢复主窗口时先停止，再显示窗口。

### FR07 托盘与生命周期

- 主窗口最小化后隐藏到托盘，快捷键继续有效，运行状态不变。
- 托盘菜单只包含“显示主窗口”“停止所有动作”“退出”，不增加新的启动路径。
- 托盘图标工具提示显示产品名、当前状态和紧急停止快捷键。
- 关闭按钮和 Alt+F4 均表示退出，必须先停止并释放；不能默认隐藏后继续连点。
- 主窗口恢复、正常退出、Windows 注销或关机通知、会话锁定以及系统挂起通知，均应触发停止与释放流程。
- 从锁屏或睡眠恢复后保持停止，不自动恢复。
- 单用户会话中只允许一个实例。同一会话重复运行时，由已有实例先停止任务，再显示主窗口，新进程退出。
- 同一用户会话的普通权限与管理员权限实例也应避免同时工作；如果受权限限制无法唤醒已有实例，新进程说明原因并退出，不启动第二个输入引擎。

### FR08 配置与本地记录

配置文件路径：`%LOCALAPPDATA%\LiteClicker\settings.json`。

至少保存以下内容：

| 字段 | 类型 | 默认值或约束 |
| --- | --- | --- |
| schemaVersion | 整数 | 1 |
| selectedMode | 字符串 | click 或 hold，默认 click |
| speedSelection | 字符串 | preset1–preset5 或 custom，默认 preset3 |
| customCps | 整数 | 1–100，默认 10；切换预设时可保留上次自定义值 |
| startDelaySeconds | 整数 | 0、1、2、3、5 之一，默认 2 |
| hotkeys | 对象 | click、hold、stop 三个主键与修饰键集合 |
| windowPlacement | 对象 | 正常窗口的位置与大小；恢复时限制在可见工作区 |

- 不保存或恢复正在运行的状态，不保存需要自动恢复的“按下”状态。
- 首次运行使用默认配置；配置损坏、缺字段或非法值时，按字段回退为合法默认值，并给出一次非阻塞提示。
- 配置包含未知版本时保留原文件备份，使用兼容字段或默认配置，不因解析异常无法启动。
- 设置提交后自动保存，使用同目录临时文件与替换方式降低写入中断风险。
- 无法写入配置时仍允许使用内存中的有效设置，提示“设置暂时无法保存，本次仍可使用”。
- 可保留必要错误日志于同一用户目录，最多 3 个文件、每个 1 MiB；不记录屏幕、输入内容、目标窗口标题或逐次点击轨迹。

## 5 GUI 设计规范

### 5.1 视觉方向

采用简洁、克制的 Windows 桌面工具风格。首版统一浅色界面，不要求暗色主题和主题切换。

| 元素 | 规范 |
| --- | --- |
| 窗口 | 默认约 520 × 620 DIP，允许缩放；最小尺寸约 440 × 540 DIP |
| 标题栏 | 优先系统标准标题栏，保留窗口管理与键盘行为 |
| 页面背景 | #F5F7FA |
| 内容表面 | #FFFFFF |
| 主文字 | #182230 |
| 次级文字 | #5B6573 |
| 主操作色 | #2563EB |
| 停止操作色 | #B42318 |
| 边框 | #D8DEE8，保持适度可见 |
| 字体 | 系统字体优先；中文采用 Microsoft YaHei UI 等系统回退字体 |
| 正文大小 | 14 DIP；主要状态可使用 18–20 DIP |
| 间距 | 以 8 DIP 为基础，卡片内边距 16 DIP，页边距 20–24 DIP |
| 控件 | 按钮高度至少 36 DIP，输入框与按钮对齐，圆角约 8 DIP |

不使用依赖联网加载的字体或图片；图标优先用简单矢量几何或随应用嵌入的本地资源。不要加入广告、无关装饰、欢迎动画或多个复杂页面。

### 5.2 页面结构

界面从上到下排列：

1. 产品标题和简短说明。
2. 状态区：状态文字、运行时间、连点计数或按住状态。
3. 模式区：“连续点击”“持续按住”两个互斥选项。
4. 速度区：五个档位按钮、自定义数字框、理论间隔。
5. 启动延迟选择。
6. 全局快捷键摘要与可展开的编辑区域。
7. 主操作区：“开始”与“停止所有动作”。
8. 底部说明：“作用于当前鼠标位置”，以及醒目的紧急停止快捷键。

开始按钮随状态显示“开始连点”“开始按住”“取消启动”或不可用状态；停止按钮在倒计时和运行期间始终可用。释放失败时保留可再次尝试停止的入口。

### 5.3 可用性

- 100%、125%、150%、200% 缩放下不得遮挡核心控件；窗口超出可用工作区时缩小并提供滚动布局。
- 支持多显示器移动；切换 DPI 后文字保持清晰，窗口不跳到屏幕外。
- Tab 顺序与视觉顺序一致，焦点标识可见，字段有可访问名称。
- 状态同时使用文字和颜色表达，不依赖红绿颜色差异。
- 不将 Enter 配为无条件开始，也不将 Esc 全局注册为紧急停止；避免与输入和其他软件操作混淆。
- 错误提示优先贴近字段或状态区。只有无法继续运行的错误才使用对话框。

## 6 状态模型与停止契约

实现以下显式状态，界面只能从统一状态源派生：

| 状态 | 含义 |
| --- | --- |
| Idle | 停止，可编辑有效设置 |
| Countdown | 等待启动延迟与启动条件，尚未发送按下事件 |
| Clicking | 连点任务运行中 |
| Holding | 已发送模拟左键按下，等待释放 |
| Stopping | 已取消新动作，正在结束任务和清理输入状态 |
| Error | 无法启动或无法确认完成清理；显示原因与处理入口 |

因快捷键或设置错误进入 Error 且没有待释放输入时，允许编辑相关设置，修复并重新验证后回到 Idle。存在待释放输入的 Error 只允许停止、诊断或明确退出；不能通过修改设置绕过清理进入新的运行。

统一停止流程按以下顺序执行：

1. 取消当前会话并使其启动令牌失效，取消倒计时与周期等待。
2. 阻止新的 LEFTDOWN 进入发送路径；停止请求不能排在大量点击任务之后。
3. 等待当前已进入临界区的输入调用完成。
4. 若本应用可能仍持有未配对的模拟按下，发送 LEFTUP 并检查结果。
5. 更新状态与统计，确认清理后才允许新的会话启动。

停止操作必须幂等：多次停止不能重启任务、增加一次点击或创建多个清理线程。停止已完成且没有待释放状态时，不反复发送 LEFTUP，以免干扰用户的正常物理操作。

若释放调用失败，可进行少量有界重试，例如最多 3 次、每次间隔不超过 50 毫秒。仍失败时进入 Error，显示“无法确认左键已释放”，保留待释放标记并禁止启动新任务，允许用户再次停止；不能直接把状态显示成正常完成。

正常关闭请求遇到上述释放失败时，保留错误界面并允许再次停止，或由用户明确选择仍然退出；系统强制关闭等无法继续交互的路径只执行有界的尽力清理。

异常清理是尽力执行机制。强制结束进程、系统崩溃、断电或切入受保护桌面时，普通进程无法保证补发抬起事件。本项目不承诺这些情况下百分之百释放，也不以新增常驻服务或驱动解决此问题。

## 7 输入引擎与计时要求

### 7.1 输入正确性

- 输入引擎与 UI 线程分离。GUI、快捷键和托盘最终调用同一个运行控制器。
- 仅一个执行路径拥有 SendInput 发送权限，通过锁、串行执行器或等效机制保证顺序。
- 正确声明 INPUT 联合体、MOUSEINPUT 和指针大小字段，使用实际结构体大小作为 cbSize，特别验证 x64 内存布局。
- 每次检查 SendInput 的实际返回数量；提交 2 个事件而只成功 1 个时，按存在待释放风险处理，停止并补偿释放。
- 持续按住只有成功提交 LEFTDOWN 后才进入 Holding。发送失败时不显示“按住中”。
- 连点完整输入对成功后才增加计数；不在请求前增加，不把异常吞掉继续运行。
- 可给本应用注入事件设置固定 dwExtraInfo 标记用于测试定位，但不得据此推断目标应用已处理事件。
- 不使用 PostMessage 给后台窗口伪造点击，不改变用户鼠标速度或系统双击参数。

### 7.2 计时与取消

- 使用 Stopwatch 或等效单调时钟计算时间和下一次计划执行点，不能依赖会被系统时间调整影响的墙上时钟。
- 不能用 DispatcherTimer 驱动核心连点，不能在 UI 线程 Sleep，也不能对每次点击创建新的线程。
- 采用可取消等待或合适的系统计时机制；不能以持续忙等维持目标频率。
- 执行迟到时跳过已错过的周期，从当前时间合理安排下一周期，禁止集中补发积压点击。
- 待机和按住状态不运行高频空循环。若申请更高计时分辨率，必须限制在需要的活动期间，并对称释放相关资源。
- 即使频率只有每秒 1 次，也要立即唤醒等待处理停止，不能等到一秒间隔结束才响应。
- UI 统计更新限制在每秒 5–10 次，不能每次点击都刷新所有绑定。

### 7.3 并发边界

- 倒计时回调、快捷键、停止、异常和退出必须经过统一状态控制。
- 每次会话拥有独立代号或 CancellationToken；旧会话回调不得启动或修改新会话。
- 控制事件顺序必须可测试，尤其是“刚到启动时刻按停止”和“按住切连点”的竞争条件。
- 已进入系统队列的输入无法撤销。应用应保证停止生效后不再提交新的按下事件；测试需要区分提交时间与目标窗口收到消息的时间。
- 停止之后发生的新的、明确的用户启动操作可以启动；停止之前遗留的启动请求必须失效。

## 8 权限与兼容性边界

应用清单使用 asInvoker，日常运行不弹出 UAC 提权提示。普通权限运行的应用通常不能向更高完整性级别的目标进程注入输入，SendInput 的错误信息也不能可靠地单独判定是否由 UIPI 导致。

需要在帮助说明中明确：

- 若目标程序以管理员权限运行，用户可选择以相同权限重新打开本工具，再自行开始操作；程序不自动提权。
- 登录界面、锁屏、UAC 安全桌面和受保护窗口不属于支持范围。
- 某些程序可能忽略合成输入；成功提交系统输入不代表目标应用必然接受。
- 默认不保证游戏、独占全屏程序或远程桌面场景的输入兼容性。

发现输入提交失败时立即停止，并给出可理解的提示，例如“输入未能发送，请检查目标窗口权限与当前桌面状态”；不得宣称已经精确识别出某一种阻断原因。

## 11 单 EXE 发布要求

### 11.1 发布契约

最终发行主文件命名为 `LiteClicker-win-x64.exe`，并包含图标、产品名称、文件版本和产品版本。双击不能出现附带控制台窗口。

用户把这一 EXE 单独复制到另一台符合条件的 Windows 11 x64 电脑后，应能离线启动并使用全部首版功能，无需安装 SDK、Desktop Runtime、额外 DLL 包或解释器。

允许发布包同时附带 README、校验值和许可说明，但它们不是运行依赖。字体、图标、默认配置和必须的运行组件均不能依赖发布目录中未说明的文件。

.NET 自包含单文件可以包含运行时，并通过 IncludeNativeLibrariesForSelfExtract 将原生库纳入文件，在启动时解包。该方案允许临时磁盘文件；本项目没有“全程零解包”要求。[R1][R2]

### 11.2 项目属性基线

以下为主应用项目的发布属性基线，应结合实际工程验证：

```xml
<PropertyGroup>
  <OutputType>WinExe</OutputType>
  <TargetFramework>net10.0-windows</TargetFramework>
  <UseWPF>true</UseWPF>
  <UseWindowsForms>true</UseWindowsForms>
  <Nullable>enable</Nullable>
  <AssemblyName>LiteClicker</AssemblyName>
  <RuntimeIdentifier>win-x64</RuntimeIdentifier>
  <SelfContained>true</SelfContained>
  <PublishSingleFile>true</PublishSingleFile>
  <IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>
  <PublishTrimmed>false</PublishTrimmed>
  <PublishAot>false</PublishAot>
  <DebugType>embedded</DebugType>
</PropertyGroup>
```

保守关闭裁剪和 Native AOT。不能为缩小文件，在没有兼容性证据的情况下更改这一决定。资源须以内嵌方式加入，避免发布时意外生成必需的外置文件。

示例发布命令：

```powershell
dotnet publish .\src\LiteClicker.App\LiteClicker.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PublishTrimmed=false -p:PublishAot=false -p:DebugType=embedded -o .\artifacts\publish\win-x64
```

构建脚本需要先确认发布输出与单文件要求相符，再将入口文件复制并命名为 `dist/LiteClicker-win-x64.exe`。不得直接从 Debug 构建目录复制一个 EXE 当作成品。

### 11.3 独立运行验证

- 使用干净 Windows 11 虚拟机或实体机，确认未预装本应用所需的 .NET 10 Desktop Runtime、SDK 或其他开发依赖；记录基线。
- 仅复制最终 EXE，断开网络，使用普通用户账户启动。
- 完成连点、按住、停止、托盘、配置保存和重新启动测试。
- 测试包含中文、空格的目录，以及 EXE 所在目录不可写但用户数据与临时目录可写的情形。
- 不提供运行所需的旁置 DLL、runtimeconfig.json、deps.json 或运行库目录。
- 使用标准临时解包目录，不要求用户配置额外环境变量。
- 签名并非首版硬性条件；如未签名须在交付说明中如实标明，不声称一定不会出现 Windows 信任提示。

## 13 Agent 实施顺序

1. 阅读本文，确认目标平台、默认值、交付路径和当前可用的构建测试环境；建立简单任务清单。
2. 建立工程、固定 SDK，并先完成最小 WPF 窗口的自包含单 EXE 发布试验，尽早验证打包可行性。
3. 实现可测试的运行控制器、状态模型、输入接口与取消流程，先通过顺序和竞争条件测试。
4. 接入 Win32 输入、快捷键、生命周期和本应用保护，用独立测试窗口验证实际行为。
5. 完成中文 GUI、配置、托盘、错误提示与 DPI 适配。
6. 执行全部验收和性能测试，修复发布阻断问题，生成正式 Release 发行物。
7. 在干净 Windows 11 环境复测实际交付的 EXE，生成校验值与测试报告后交付。

若 Agent 只能在 Linux 或 macOS 环境工作，可以实现可验证的纯逻辑并尝试受支持的交叉构建，但必须清楚区分“已构建”“已通过逻辑测试”和“已在 Windows 验证”。不能把跨平台编译成功当成 WPF、Win32 输入或独立 EXE 已通过验收，也不能编造不存在的 Windows 测试结果。

环境不足时，应完成当前可完成的部分，附可复现的 Windows 构建和测试步骤，并列出阻塞项。存在 Windows 核心验收未执行时，整体状态应标注为“待 Windows 验证”。
