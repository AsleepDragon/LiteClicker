# 实现边界

`RunController` 是输入所有者。GUI、全局热键、托盘、会话通知和退出都进入同一控制器；只有它调用 `IInputInjector.Send`。每次控制请求先增加 generation 使旧请求失效，再取消会话；命令信号量只串行化控制请求，不排队点击。输入临界区包含最终代号检查和单次原生调用。停止等待已进入的调用，随后由工作任务完成有限释放。

每个会话在后台任务执行，CancellationToken 可唤醒延迟。单调时钟计划下一次点击，迟到跳过积压周期。按住只发一次 DOWN，后续 25 ms 检查自身窗口；点击每次发送前检查。UI 每 100 ms 读取不可变快照，没有按每个输入事件刷新绑定。Windows 时钟只在连点活动期间成对调用 timeBeginPeriod(1)/timeEndPeriod(1)，不持续忙等。

SendInput 成功数量必须符合请求：连点 2、按住 1、释放 1。部分点击成功保留待释放标记，失败只计完整成功输入对；释放最多 3 次，间隔 25 ms，重试不使用已取消的运行令牌。释放失败保留标记、进入 Error，UI 不允许启动或编辑绕过清理。正常退出可重试或由用户明确退出。系统终止仅尽力清理。

`HotkeyManager` 在 UI 线程事务式切换三组注册，失败后注销候选并完整恢复旧配置。注册器使用 MOD_NOREPEAT。初始或恢复失败时禁用所有启动入口；紧急停止 GUI 仍可使用。松键等待和延迟共享会话起点，不在松键后重新延迟。

窗口保护使用 WindowFromPoint 和 HWND 所属进程，包括子窗口，不依赖矩形或正坐标。单实例使用用户 SID + 会话 ID 命名 mutex，已存在或权限不足均不启动新引擎。唤醒使用带超时的已注册窗口消息，接收端在回复前停止；UIPI 失败会说明并退出。

设置使用不可变快照、字段校验、同目录随机临时文件、flush 与覆盖重命名。运行状态不入配置。未知版本先备份；失败不自动覆盖。配置及可选停止摘要不在输入临界区中写磁盘。

WPF 采用系统标题栏、浅色样式和固定底部操作区，主体滚动。PerMonitorV2 清单负责 DPI；原生像素工作区限制窗口以兼容负坐标。具体多屏/DPI 行为仍待 Windows 验收。

当前未实现后台点击、右键、宏、驱动、自动提权、服务或联网。Windows 真实行为未通过本 Linux 环境验证，不能依据抽象测试推断系统和目标应用接受输入。
